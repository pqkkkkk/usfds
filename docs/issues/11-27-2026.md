## ISS-046: Insight & Report metric formula inaccuracies and missing real-world FDS analytics
<!-- [26-11-27] -->
- **Status:** Planned <!-- [26-11-27] -->
- **Type:** improvement · **Area:** insight-report, server, worker, web · **Priority:** P2
- **Plan:** `.plan/insight_report_fds_upgrade.md` <!-- [26-11-27] -->
- **Facts [26-11-27]:**
  - Formula/semantic bugs in `usfds-core/src/usfds_core/services/insight_report/engine.py`:
    - `insult_rate` (`engine.py:480`) computes `fp_count / max(1, flagged_count)` (False Discovery Rate including pending alerts) instead of Customer Insult Rate `FP / (TN + FP)`; `volume_insult_rate` (`engine.py:481`) is unused on UI.
    - `verified_fpr` (`engine.py:809`) computes `fp / ver_cnt` (`= 1 - precision`, i.e. False Alert Rate / FDR) instead of FPR.
    - Missing False Negative / missed-fraud metrics (`Missed Fraud $`, `Value Detection Rate (VDR)`, `Net Fraud Loss bps`), and `REJECT` (Hard False Decline) is conflated with `REVIEW` (Soft Friction) (`engine.py:438-441`).
    - 4-stage funnel (`engine.py:530-548`) is non-monotonic under Dataset Fallback (Stage 4 counts all evaluated `v_transactions`, which can exceed Stage 3 `total_cases`).
    - `score_calibration` (`engine.py:831-859`) labels True Negatives (`effective_label = 0`) in low bins as `false_positive_count` ("Giao dịch dương tính giả" in `EffectivenessTab.tsx:320`).
    - `threshold_simulator` (`engine.py:861-913`) supports only a single threshold, compares Model-only `sim_fp` against Hybrid `baseline_fp`, and hides dollar impact / Net Savings on UI.
    - `financial_trends` (`engine.py:551-582`) groups by `job_id` instead of `tx_timestamp` day/week and calls alert rate `fraud_rate`; `hourly_distribution` (`engine.py:991`) mixes `fraud_tx` and `flagged_tx` on the same curve; `top_flagged_subjects` (`engine.py:1064-1079`) filters `WHERE is_flagged = 1` so `total_tx_count == flagged_tx_count`.
  - Underutilized data already available in USFDS: `ProjectWarehouse` extracts 5 optional entity columns (`device_id`, `ip_address`, `card_id`, `merchant_id`, `merchant_category`, `project_warehouse.py:35-41`); `Case` stores `created_at`, `resolved_at`, `resolved_by`, `priority` (`case.py:54-64`) for SLA/MTTR; `ModelVersionRepository` exists (`providers/repos.py:66-67`) for model labels/comparison.
  - UI/Export issues: hardcoded `"XGBoost"` labels (`EffectivenessTab.tsx:111,142,289`, `ComplianceReportCenterTab.tsx:310,313`), mixed English/Vietnamese copy, and HTML export wraps raw markdown in `<pre>` (`report_builder.py:503-519`).
- **Direction:** Benchmark against real-world FDS governance/validation practices (including Jube `aml-fraud-transaction-monitoring`). Fix all metric formulas, add Missed Fraud / VDR / bps, REJECT vs REVIEW friction split, Case SLA (`CRITICAL ≤ 4h`, `HIGH ≤ 24h`, `MEDIUM ≤ 72h`, MTTR P50/P90, Backlog Aging, Analyst Consistency), Rule `FAR` / `Unique Catch` / `Small Sample (n < 30)` / FP & FN samples, true Calibration Reliability Curve (`Uniform` + `Equal-Count`, Brier, ECE), Top-K Lift/Gain + KS, Dual-Threshold Cost-Aware Simulator displaying both Hybrid (AI + Rules) and Model-only side-by-side, Model Comparison + PSI Score Drift, multi-entity Segment Hit-Rate Matrix, Watchlist Impact, `MetricInfoTooltip` UI guidance, and styled HTML/Print-to-PDF export. Spec synced in `docs/features/insight_report/suc-spec.md`.
