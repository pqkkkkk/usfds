## Security

## ISS-013: Third-party API key committed to git
- **Status:** In progress — untracked 26-11-14; user must rotate key (still in git history)
- **Type:** security · **Area:** agent, devex · **Priority:** P0
- **Plan:** Phase 0 (untrack); key rotation by user
- **Impact:** `usfds-agent/.env` (contains `GEMINI_API_KEY`) is tracked by git, and the repo has a GitHub remote. The key is exposed to anyone with repo access and remains in history.
- **Fix:** Rotate the key → `git rm --cached usfds-agent/.env` → add to `.gitignore` → ship `usfds-agent/.env.example`. Also untrack `usfds-server/.env`, `usfds-web/.env` (harmless values today, same pattern).

## ISS-014: CORS allows every origin together with credentials
- **Status:** Open
- **Type:** security · **Area:** server · **Priority:** P1
- **Plan:** `.plan/user_management_rbac.md` Phase 3 (`USFDS_CORS_ORIGINS`)
- **Impact:** `allow_origins=["*"]` + `allow_credentials=True` (`usfds-server/src/usfds_server/api.py:50-57`). Once auth exists, any site could make credentialed requests.

## ISS-015: Server reads arbitrary filesystem paths supplied by clients
- **Status:** Open
- **Type:** security · **Area:** server, worker, data-management · **Priority:** P1
- **Plan:** — (fix with ISS-006 Phase 3)
- **Impact:** In client-server mode, a client can make the server read any local file.
  - Dataset import accepts any server `file_path` (`ingestion.py`, `Path.is_file()` branch).
  - `_load_artifact_dataframe` falls back to `Path(artifact_path).read_bytes()` (`usfds-server/src/usfds_server/routers/rule_router.py:329-342`; duplicated in `usfds-worker/src/usfds_worker/handlers.py:82-90`).
- **Direction:** Only accept storage keys in client-server mode; restrict local paths to desktop mode.

## Bugs

## ISS-017: `delete_dataset` never deletes artifact files
- **Status:** Open
- **Type:** bug · **Area:** data-management · **Priority:** P1
- **Plan:** — (Phase 1, task A1, together with ISS-003)
- **Root cause:** `DataManagementService.delete_dataset` calls `self.artifact_repo.get_by_dataset_id(...)` (`usfds-core/src/usfds_core/services/data_management/service.py:119`). The method does not exist (the interface method is `list_by_dataset`). The `AttributeError` is swallowed by `except Exception: pass`, so per-artifact files stay in storage forever.

## ISS-018: Case filter by rule code only works on SQLite
- **Status:** Open
- **Type:** bug · **Area:** investigation, infra · **Priority:** P1
- **Root cause:** `func.json_each(CaseModel.triggered_rule_codes)` (`usfds-infra/src/usfds_infra/database/case_repositories.py:76`) is SQLite syntax. On PostgreSQL, `json_each` expects an object; arrays need `json_array_elements(_text)`. The test suite runs only on SQLite, so this is never caught.

## ISS-019: Async plugin-upload endpoint blocks the event loop
- **Status:** Open
- **Type:** bug · **Area:** server · **Priority:** P1
- **Root cause:** `upload_and_register_plugged_model` is `async def` (`training_router.py:211`) but calls the blocking `enqueue_and_wait` (polls up to 300 s) in queue mode → every other request on that worker process stalls.

## ISS-020: No schema migrations for existing tables
- **Status:** Resolved (26-11-14) — Alembic baseline `0001_baseline`, idempotent for legacy DBs; verified on a copy of the demo DB (all rows kept)
- **Type:** bug · **Area:** infra · **Priority:** P0
- **Root cause:** Startup runs `Base.metadata.create_all` (`usfds-infra/src/usfds_infra/database/session.py:58-61`), which never alters existing tables, plus one hand-written SQLite-only migration (`case_migration.py`). Any new/changed column is silently missing on existing databases, especially PostgreSQL.
- **Direction:** Alembic with a baseline revision equal to the current schema; existing databases are `stamp`-ed, so data is preserved.

## ISS-028: Web API client swallows errors
- **Status:** Open — assessed 26-11-14, migration deferred
- **Type:** bug · **Area:** web · **Priority:** P1
- **Root cause:** Every method of `usfds-web/src/api/client.ts` (lines 65-107) catches errors and returns `{success:false}`, so react-query never enters its error state, and error UI and retries do not fire.
- **Assessment [26-11-14, F5]:**
  - The impact is smaller than first stated. The react-query hooks (`useProjects`, `useDataset*`) and the `unwrap` helpers in `investigationApi` / `insightReportApi` already throw when `!res.success`.
  - Making the client throw would break 61 `apiClient` calls across 9 api modules and 50 `.success`/`.error` checks across 20 files: 8 imperative components, the partial-failure `Promise.all` loads (`ModelHubView`, `TrainingWizardView`, `RuleDryRunWorkspace`, `DetectionJobWizardView`), and 4 probe/fallback calls.
  - Proposed migration, module by module, together with ISS-032 or ISS-005:
    1. Add an `ApiError` type and make the client methods throw.
    2. Remove the `!res.success` checks that become dead code.
    3. Move the 8 imperative components to try/catch or `useQuery`.
    4. Change the partial-failure loads to `Promise.allSettled`.
