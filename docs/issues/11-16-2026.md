## ISS-037: Feature visibility gating by ActorContext and missing router permission enforcement
- **Status:** Resolved (26-11-16) <!-- [26-11-16] -->
- **Type:** feature · **Area:** auth, server, web · **Priority:** P1
- **Plan:** `.plan/rbac_feature_visibility.md`
- **Impact / Root cause:**
  - `usfds-web` only gates 3 UI points (`UserAccountMenu.tsx:14`, `AdminUsersPage.tsx:25`, `ProjectMembersSection.tsx:9`); `Sidebar.tsx`, `OmnisearchModal.tsx`, routes in `App.tsx`, project portal/settings, and all module actions are visible regardless of `ActorContext` roles/permissions.
  - `seed_rbac.py` and `rule_router.py` include `rule:propose` (invalid permission), `user_router.py`/`authz_service.py` check `"user:manage"` instead of `user:update`/`user:reset_password`, `list_project_members` checks `project:read` instead of `project_member:read`, `detection:export` & `case:create` are missing, and several sub-endpoints in `dataset_router`, `rule_router`, `training_router`, `detection_router`, `investigation_router`, `insight_report_router` lack `authz.require_project_permission(...)`.
- **Direction / Fix:**
  - Remove `rule:propose` (Phương án A: `fraud_analyst` holds `rule:read` only; `data_scientist` holds `rule:read/create/update/delete/dry_run/deploy/undeploy`), add `detection:export` & `case:create`, fix `user:update`/`user:reset_password`/`project_member:read`, and enforce `authz` on all router endpoints.
  - Implement centralized `feature-policy.ts` + `useActorContext` hook reusing `/api/v1/auth/me` `ActorContext`, hide unauthorized UI features/actions, and add route guards in `usfds-web`.
