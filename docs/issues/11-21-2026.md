## ISS-042: Missing `project_id` enforcement and cross-project authorization bypasses on list, get-by-id, and related endpoints
- **Status:** Planned <!-- [26-11-21] -->
- **Type:** security · **Area:** auth, server, training, data-management, rule-engine, detection, storage, web · **Priority:** P0
- **Plan:** `.plan/project_scoped_access_control.md`
- **Impact / Root cause / Facts:**
  - `GET /api/v1/datasets` (`usfds-server/src/usfds_server/routers/dataset_router.py:183-201`): `project_id` is optional; when omitted, `dataset:read` check is skipped and fallback only checks `ds.project_id in member_pids`.
  - `POST /api/v1/datasets/import` (`dataset_router.py:106-118`, `dataset_api_schemas.py:14`, `ingestion.py:116`): `project_id` is optional; when omitted, `dataset:create` check is skipped completely and an orphan `uuid4()` project ID is generated.
  - `GET /api/v1/training/models`, `/models/{id}`, `/models/{id}/versions`, `/versions/{id}`, `/versions/{id}/lineage`, `/runs`, `/runs/{id}`, `/runs/{id}/lineage` (`training_router.py:352-648`): `project_id` is optional or absent; `if entity.project_id is not None:` skips authorization completely when `project_id IS NULL`. `TrainingOrchestrationService.list_training_runs` (`training_service.py:482-486`) also leaks `r.project_id is None` into project-scoped queries (`r.project_id == project_id or r.project_id is None`).
  - `POST /api/v1/training/runs` (`training_router.py:534-568`, `training_api_schemas.py:38`, `training_service.py:96-168`): `project_id` is optional and service does not verify `dataset_artifact_id` or `model_id` belongs to `request.project_id` (cross-project training data access).
  - `GET` by ID endpoints in `dataset_router.py:204-301`, `training_router.py:377-648`, `detection_router.py:119-259`, `rule_router.py:139-253` do not accept `project_id` and fetch from DB before checking permissions (404 vs 403 ID existence oracle and no caller project-context verification).
  - `rule_router.py:301-302, 415, 447-448`: `evaluate_single_rule` and `backtest_rule_on_dataset` load `version_id` without checking `target_version.rule_id == rule.rule_id`, and `backtest_rule_on_dataset` skips project check if `dataset is None`.
  - `GET /api/v1/storage/presigned-download` (`storage_router.py:108-158`): does not require `project_id`, infers project UUID from the first UUID segment in `object_key` (fails on `datasets/{dataset_id}/...` and `exports/detection/{job_id}/...`, vulnerable to crafted paths), and only checks `project:read`.
- **Direction / Fix:**
  - Enforce mandatory `project_id: UUID` on all project-scoped `list` and `get by id` endpoints (matching `investigation_router.py` pattern), `POST /datasets/import`, `POST /training/runs`, and `GET /storage/presigned-download`; check project permission before DB/storage reads; verify resource belongs to `project_id` (returning `404` on mismatch and blocking `project_id IS NULL` for non-builtin resources); validate cross-project references in training and rules; update `usfds-web` API clients/hooks/components and tests.

## ISS-043: `GrantScope.OWN` access control not enforced across routers and missing `owner_id` on domain tables
- **Status:** Open <!-- [26-11-21] -->
- **Type:** bug · **Area:** auth, server, infra, training, rule-engine, detection, investigation · **Priority:** P1
- **Plan:** —
- **Impact / Root cause / Facts:**
  - `access_logic.py:131-132` (`can_access_record`) requires `resource.owner_id is not None and actor.user_id == resource.owner_id` when `scope == GrantScope.OWN`, and `authz_service.py:90` (`require_project_permission`) defaults `owner_id: Optional[UUID] = None`.
  - No router (`project_router.py`, `dataset_router.py`, `training_router.py`, `detection_router.py`, `rule_router.py`, `investigation_router.py`) passes `owner_id` to `require_project_permission(...)`, so any role holding a permission with `GrantScope.OWN` gets `403 Forbidden` on `get by id` and `mutate` endpoints even for its own resources.
  - Only `GET /api/v1/projects` (`project_router.py:109-111`) uses `authz.can_list(...)` and filters by `owner_id`; all other `list` endpoints (`datasets`, `models`, `training/runs`, `rules`, `detection/jobs`, `cases`, `blacklist`) call `require_project_permission(..., owner_id=None)` and fail with `403` instead of returning own records.
  - Domain entities/tables `Rule` (`rule.py:31`), `DetectionJob` (`detection.py:62`), `TrainingRun` (`model.py:73`), `ModelVersion` (`model.py:49`), and `Case` (`case.py:57`) only store `created_by`/`registered_by`/`assigned_to` as username strings (nullable) rather than `owner_id: UUID`.
- **Direction / Fix:**
  - Add `owner_id` (UUID, nullable for legacy rows with backfill where possible) via Alembic migration for `rules`, `detection_jobs`, `training_runs`, `model_versions` (and define ownership semantics for `cases`).
  - Update `list` endpoints to use `authz.can_list(...)` and filter by `qf.owner_id` when `GrantScope.OWN` applies.
  - Update `get by id` and `mutate` endpoints to check project-level permission membership first (`effective_scope(actor, perm, project_id) is not None` -> `403`), fetch scoped by `(project_id, id)` (`404`), then enforce `require_project_permission(..., owner_id=entity_owner_id)` (`403` on `OWN` mismatch).
