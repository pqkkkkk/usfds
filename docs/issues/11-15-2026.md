## ISS-036: Dataset import & exports inconsistent across S3 presigned and Electron local modes
- **Status:** Resolved (26-11-15)
- **Type:** bug · **Area:** web, storage, server · **Priority:** P1
- **Plan:** `.plan/presigned_upload_and_file_io_guard.md`
- **Impact / Root cause:**
  - `useDatasetImport.ts` and `DetectionJobWizardView.tsx` fabricated `../datasets/<name>` in browser mode when `window.electronAPI` was absent, and `useDatasetImport.ts` sent a hardcoded mock `user_id`.
  - `insightReportApi.exportReport` excluded `format === 'html'` from presigned URL download on S3, and local fallback exports (`datasetApi.ts`, `detectionApi.ts`, `insightReportApi.ts`) bypassed `apiClient.getRawAxios()` (omitting Bearer auth).
- **Fix:** Updated `storageApi.ts`, `useDatasetImport.ts`, `ImportDatasetModal.tsx`, `DetectionJobWizardView.tsx`, and the three export APIs (`datasetApi.ts`, `detectionApi.ts`, `insightReportApi.ts`); `dataset_router.import_dataset` now uses `actor.user_id` and `actor.username`.
